Write sections of the plan draft. Each section sent replaces that section; the rest stay as they are.
The draft shows beside the conversation as it grows. It is not submitted.

title: the change, in a few words.
goal: what the change is for, the approach taken and the one not taken.
code: each file to change, with the functions or sections in it and what changes there.
tests: each unit test to add or change, and what it asserts.
validation: the commands to run, and what to check by hand or against a running instance.
migration: stored data, config or API shapes that change and how. Write None when nothing does.
risks: what could break: callers, behaviour a user sees, performance.
steps: the work in order, one line each, naming its files. They become the todo list.
open: what is still undecided. Leave it empty when nothing is.
